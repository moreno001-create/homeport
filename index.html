How it works

Every visit, guided in safely

Each app gets its own address and runs in its own containers, reachable only from the server itself. Caddy, the web server in front, is the single way in: it handles HTTPS and asks Homeport who's allowed through.

  1. Someone opens cloud.example.com

    Caddy answers over HTTPS, with a certificate it got from Let's Encrypt on its own.

  2. Caddy asks Homeport: may they come in?

    Not signed in yet: they go to your portal to sign in once, then straight back to the page they wanted.

  3. Homeport checks their groups

    Each app is open to the groups you choose, like "family" or "work", or to anyone.

  4. The app gets the visit, and their name

    Apps that support it sign the person in automatically. A browser can't fake that name: Homeport strips it and sets it itself.

Single sign-on

One account for the whole household

Add people once, put them in groups, and they sign in once. Apps that speak OpenID Connect, like Nextcloud and Vaultwarden, offer "Log in with Homeport" and create the account the first time someone uses it, bringing their groups along.

Passwords are stored as Argon2id hashes, sign-in links work only once, and wrong passwords are slowed down per address.

AI helpers

A capable deckhand, on a short line

Homeport gives AI agents a safe set of tools over MCP, the open protocol agents use. Connect opencode, Claude Code or any MCP client with homeport mcp, and ask it to install an app, find out why something is slow, or tidy up. It can look around freely; it can't change anything without you.

look · runs straight away

Look

  • List apps, their status and settings
  • Read app, Caddy and system logs
  • Check health: load, memory, disk
  • Check a domain's DNS and certificate
change · you approve each one

Change

  • Install, update, restart or remove apps
  • Change who can open an app
  • Add domains, set people's groups
  • Run an app's own admin tool
shell · off unless you turn it on

Shell

  • Any command on the server
  • Each command needs your approval
  • Stops after two minutes

Agents that hand over cleanly

A shared notebook records what was done to which app, what each app's quirks are, and any work left half-finished. Switch from one agent to another, or come back next week, and the work carries on where it stopped.

Secrets never reach the AI: passwords, tokens and keys are replaced with dots in everything it sees, and every call is written to an audit log you can read in the admin panel.

Local and cloud AI coming next

Small jobs at home, hard ones to Claude

Homeport's own assistant will send everyday questions ("what's running?", "summarize this log") to a model on your own hardware, and hand anything tricky to Claude, along with everything done so far. It will watch how busy your machines are and respect your rules: local only, ask before using the cloud, or a monthly limit.

An Apple Silicon Mac makes a great model server: a small Linux box can run Homeport and the apps, while the Mac's memory does the thinking.

Under the hood

Small, plain, and yours

One binary

The service, the command line and the admin panel are a single Go program of about 10 MB.

Containers

Every app is a Docker Compose project with its own folder, listening only on 127.0.0.1.

Caddy

Automatic HTTPS for every domain. Homeport writes the config, has Caddy check it, then reloads.

Open standards

OpenID Connect for sign-in, MCP for AI agents. Nothing proprietary in the way.

Homeport is early (version 0.4). It's tested on Ubuntu 26.04 virtual machines and on an Apple Silicon Mac; it hasn't yet run on a public server with real Let's Encrypt certificates, and the Mac installer is a preview. Try it on a spare machine first.
